# System design & review rules

## Architecture

Island состоит из двух процессов и четырёх слоёв.

```
WebView (TypeScript)                    Rust (Tauri)
┌──────────────────────────────┐        ┌────────────────────────────┐
│ ui/      разметка, события   │        │ window_api.rs  окно, Win32 │
│ services/ состояние + I/O    │◀──────▶│ metrics.rs     sysinfo     │
│ core/bridge.ts  единственный │ invoke │ media.rs       SMTC (WinRT)│
│ core/    журнал, наблюдатели │        │ main.rs        сборка      │
│ lib/     чистые функции      │        │                            │
└──────────────────────────────┘        └────────────────────────────┘
```

- **Слои:** `ui → services → core/bridge → Rust`. Зависимости идут только внутрь.
- **`ui/`** знает про DOM и ничего не знает про `invoke`. Раздел получает
  зависимости через `AppContext` (оболочка, настройки, уведомления) — сервисы
  не создаются «на месте».
- **`services/`** держат состояние и побочные эффекты, но не трогают DOM;
  изменения отдают через `Emitter`. Применение темы и размеров окна — работа
  оболочки (`main.ts`), а не сервисов.
- **`lib/`** — чистые функции без DOM, сети и состояния: их можно покрыть тестами
  без окружения.
- **`core/bridge.ts`** — единственная точка вызова Rust. Любая нативная
  возможность необязательна: без Tauri интерфейс остаётся работоспособным.
- **Rust-модули** изолированы по ответственности; команды помечены
  `#[tauri::command(async)]`, если могут блокировать поток событий.
- **Окно** двигает только `main.ts` (через `dock_window`) и Rust при старте.

## Review rules

- **Никакого `console.log`** в коде: пишем через `core/logger.ts`. `console.warn` /
  `console.error` допустимы только внутри самого журнала.
- **Ошибки не глотаются:** каждый `await` сетевого или нативного вызова либо
  обёрнут (`call`, `try/catch`), либо обработан через `.catch`; причина попадает
  в журнал (`log("warn" | "error", …)`).
- **Секреты:** ключи API и токены не хардкодятся — только из настроек пользователя.
- **Внешний текст экранируется:** названия треков, имена процессов, названия
  городов и ответы модели вставляются в `innerHTML` только через `escapeHtml`.
- **Системные действия — только по белому списку.** `open_target` принимает
  фиксированный набор строк; произвольная команда из WebView невозможна.
- **Именование:** функции — глаголы, типы — PascalCase-существительные,
  файлы — по ответственности (`services/media.ts`, `ui/pages/system.ts`).
- **Документация:** каждый экспортируемый модуль и функция имеют doc-комментарий
  с описанием входов и поведения при ошибке.
- **Производительность:** опрос защищён от наложения запросов (`busy`-флаг),
  справочники вынесены из функций в константы модуля, раздел монтируется только
  когда панель раскрыта, обложка трека кэшируется в Rust.
- **Доступность:** интерактив — настоящие `button` с `aria-expanded` /
  `aria-checked` / `aria-selected`; поддерживается `prefers-reduced-motion`;
  `Esc` сворачивает панель.
- **Тесты:** чистые функции (`lib/format.ts`, `parseIntent`, парсеры ответов)
  не зависят от DOM и сети — их можно покрывать точечными unit-тестами без
  изменения кода. Сейчас гейт качества — `npm run build` (`tsc` + `vite build`);
  тест-раннер в проект не подключён, и это осознанное решение, а не забытый шаг.
